## Task Checklist

### 1. Extend `web/src/hooks/useGhostRoom.ts` for Hybrid Online + Offline Direct Handshake
- [x] **1.1 Add Offline Direct State & Actions to `GhostRoom` interface:**
  ```ts
  export type OfflineHandshakeStep =
    | 'idle'
    | 'host-waiting-for-reply'
    | 'guest-showing-reply'
    | 'connected'

  // Add to GhostRoom interface:
  /** True when the room is operating in serverless Offline Direct WebRTC mode. */
  isOfflineDirect: boolean
  /** Current step in the 2-way offline QR / code handshake. */
  offlineStep: OfflineHandshakeStep
  /** Compact Offer token (GD1...) generated by the Host for its QR code and Copy Offline Code button. */
  offlineInviteToken: string | null
  /** Compact Answer token (GD1...) generated by the Guest after scanning/pasting the Host's Offer. */
  offlineReplyToken: string | null
  /** Accepts either a Host Offer token (on Guest) or a Guest Answer token (on Host). Returns true on success. */
  acceptOfflineToken: (rawInput: string) => Promise<boolean>
  /** Manually activates Offline Direct Mode immediately (e.g. on a flaky hotspot). */
  activateOfflineDirect: () => Promise<void>
  ```
- [x] **1.2 Prepare `OfflineDirectEngine` in Parallel / Automatic Failover:**
  - Keep an `offlineEngineRef = useRef<OfflineDirectEngine | null>(null)` alongside `engineRef` (`PeerJsEngine`), wired to the **exact same** `ChunkReceiver`, packet handler (`TEXT`, `FILE_START`, `FILE_CHUNK`, `FILE_END`, `FILE_ACK`, `ITEM_NUKE`), binary handler, progress publisher, and `peer:join` / `peer:leave` listeners!
  - Create a helper `activeEngine()` that returns whichever engine currently has an open peer connection (`offlineEngineRef.current?.peers.length ? offlineEngineRef.current : engineRef.current`), so `sendText`, `sendFiles`, `copyItem` (`ITEM_NUKE`), `saveItem`, and `burnItem` work identically whether the peer linked via `PeerJsEngine` or `OfflineDirectEngine`!
  - **Host Offer Pre-Generation & Automatic Offline Failover:**
    - Whenever `session.role === 'host'` and `session.roomCode` exists, start `offlineEngine.startHostOffer(...)` in the background right away so `offlineInviteToken` (`GD1...`) is ready within `~200ms`!
    - Why pre-generate `offlineInviteToken` on the Host?
      1. The Host's QR code on `HomeHub` (`RoomCodeCard`) immediately includes `#gd=${offlineInviteToken}` in its `joinUrl` (`/join?room=XXXXXX#gd=GD1...`)!
      2. If the two devices are **online**, `PeerJsEngine` connects automatically in 1 scan and ignores `#gd=...`.
      3. If the two devices are **completely offline** (or `PeerJsEngine.connect()` fails after the fast `~2.5s` timeout because Wi-Fi/hotspot has no internet), `isOfflineDirect` flips to `true`, `offlineStep` becomes `'host-waiting-for-reply'`, `status` stays `'connecting'` (not a dead-end error!), and the Guest who scanned that QR **already has the Host's Offer token in `#gd=...`** without needing to re-scan the Host!
  - **Guest Automatic Offer Consumption & Reply Generation:**
    - When `acceptOfflineToken(rawInput)` is called (either automatically from `window.location.hash` `#gd=...` or from `QrScannerModal`):
      - Extract the token with `extractCompactTokenFromInput(rawInput)` and decode with `decodeCompactSdp(token)`.
      - If the decoded token is an **Offer (`payload.t === 'o'`)**:
        - Ensure the guest joins `payload.r` (if not already in that room), call `offlineEngine.acceptOfferAndCreateAnswer(token, ...)`, store the resulting answer token in `offlineReplyToken`, set `isOfflineDirect = true`, set `offlineStep = 'guest-showing-reply'`, and announce `buildFeedback('INFO_OFFLINE_REPLY_READY')`.
      - If the decoded token is an **Answer (`payload.t === 'a'`)**:
        - Call `await offlineEngine.acceptAnswerToken(token)`. Once connected, `offlineStep` becomes `'connected'` and `'peer:join'` fires `SUCCESS_PEER_JOINED`!
      - If invalid, announce `buildFeedback('ERR_OFFLINE_CODE_INVALID')` and return `false`.
- [x] **1.3 Add Automatic Network-Change Recovery (`online` / `connection.change`):**
  - In `useGhostRoom.ts`, subscribe to `window.addEventListener('online', ...)` and `(navigator as Navigator & { connection?: EventTarget }).connection?.addEventListener('change', ...)`.
  - When a network event fires and `peers.length === 0` and `status === 'error'`, automatically call `reconnect()` so turning on Wi-Fi or hotspot after opening the cached app recovers hands-free.
